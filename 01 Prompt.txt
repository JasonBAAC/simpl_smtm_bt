컴퓨터를 이용하여 가상화폐를 자동거래하는 프로젝트를 구현하려고 해. 다음의 내용을 참고하여 PRD를 작성해줘.

ㅇ 큰 기능단위는 data provider, strategy, trader, analyzer와 operator로 구성

ㅇ argument를 통해 여러 mode를 설정. 시뮬레이션 vs 실제 거래, API 수신 데이터의 DB 저장 여부, 거래종목 수, 투입금액 등을 결정

ㅇ 거래소는 bithumb 으로만 한정. pybithumb 패키지를 통한 데이터 송수신

[0] 단계별 진행 상황은 모두 logging

[1] data provider에서는 pybithumb.get_current_price('ALL')와 pybithumb.get_orderbook("ALL")을 통해 전체 자산의 데이터를 5초마다 수신

[2] data provider에서는 시뮬레이션 mode 일때 위 수신한 데이터를 자산별로 SQLite에 저장

[3] strategy에서는 5초마다 수신한 pybithumb.get_current_price("ALL") 데이터 중 closing_price의 5초전 금액 대비 증가율(price_rate)을 계산

과 이 모두 양의 값을 가지면서 moving average를 계산 (40초간 10초 간격 3구간)

[4] strategy에서는 5초마다 수신한 pybithumb.get_current_price("ALL") 데이터 중 units_traded의 5초전 수량 대비 증가율(units_rate)을 계산

[5] strategy에서는 20초간 5초 간격 3구간을 windowing 해 가면서 price_rate 와 units_rate가 모두 양의 값을 가지면서, moving average 값이 큰 상위 n개 자산을 선정(n의 max가 4개 이며, 이에 못 미치는 경우도 있을 수 있음)하여 pocket에 저장

[6] 위 [1]부터 [5]까지의 과정은 계속 반복

[7] trader에서는 strategy에서 제공한 상위 n개 자산 중 첫번째 자산에 대해 투입금액 / n 한 금액으로 시장가 매수 진행(매수금액). 10초이내 시장가 매수가 완료되지 않으면 매수 요청 취소

[8] trader에서는 현재가(가장최근의 closing_price)가 매수금액 대비 증감율을 계산

[9] 위 증감율이 -3%가 되면 시장가 매도 진행

[10] 매수 요청이 나간 자산은 pocket에서 제외

[11] 나머지 자산에 대해서도 위 [7]부터 [9]까지의 과정을 반복하되, threading과 class Worker를 이용하여 병렬처리 수행. pocket 내 순위 승진하며 위 [5]에서 정보 수령

ㅇ operator에서 텔레그램으로 위 [5], [7], [9], [11] 단계 정보를 축약하여 전송

ㅇ 전체 스타일은 https://github.com/msaltnet/smtm.git을 참고하되 축약하여 구현
